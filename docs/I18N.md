# Translations

ModelCrate deliberately supports two UI languages. Spanish system locales use Spanish; all other locales use English. `i18n.detect_language()` is deterministic and tested. `MODELCRATE_LANGUAGE=en|es` overrides detection for previews or troubleshooting.

Spanish source strings are passed to `tr()`; `locales/en.json` contains the English translations. This small catalog uses only Python's standard library. The application imports it before GTK and sets `LANGUAGE` in its own process so GTK's standard strings also follow the selected language. It never edits desktop/system locale settings.

For dynamic values, translate the template before formatting:

```python
tr('Iniciando descarga de {0}…').format(name)
```

Do not translate model identifiers, API keys, paths, file names or server status identifiers. Upstream error messages and authors' model cards are displayed as received. Local audit event identifiers and directory names stay stable across languages.

Add every new user-visible Spanish message and its English translation to the catalog. Preserve numbered placeholders and format specifications exactly; automated tests check both and verify that every literal `tr()` call has an entry. Test changes in a graphical session with:

```sh
MODELCRATE_LANGUAGE=es python3 scripts/ui_smoke.py es
MODELCRATE_LANGUAGE=en python3 scripts/ui_smoke.py en
```

These UI checks mock the model list and catalog; they do not access the network or alter models. Backend tests are run by CI in both languages.

Screenshots are generated in English by default:

```sh
python3 scripts/screenshots.py --theme dark
python3 scripts/screenshots.py --theme light
```

`--language es` generates separate `*-es.png` previews without replacing the English README images. Screenshots use demo data.
